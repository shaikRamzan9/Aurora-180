# Day 002 – Variables and Object References

## What I Learned

Today, I learned how variables are assigned to objects and how objects are created in Python. I understood that variables do not store values; instead, they are names that refer to objects.

I also learned the rules for creating valid variable names and how Python supports dynamic typing, where a variable can refer to different types of objects during execution.

I understood the difference between mutable and immutable objects and how they behave when multiple variables refer to the same object.

I learned about list assignment and how assigning one list to another variable creates another reference to the same object.

Finally, I learned the difference between shallow copy (`copy()`) and deep copy (`deepcopy()`), and how they create and manage object references differently.

---

## Mistakes I Made

1. I used to say that a variable "stores" a value instead of saying that it "refers" to an object.
2. I misunderstood how object references work when assigning lists.
3. I was confused about the difference between `copy()` and `deepcopy()`.

---

## What I Learned from My Mistakes

- A variable is a name that refers to an object.
- Assignment creates a new reference, not a new object.
- Lists are mutable, so changes made through one reference affect all variables referring to the same list.
- `copy()` creates a new outer object but shares nested objects.
- `deepcopy()` creates completely independent objects.

---

## Key Takeaways

- Variables refer to objects.
- Objects have identities, which can be checked using `id()`.
- Mutable objects can be modified after creation.
- Immutable objects cannot be modified; operations create new objects instead.
- Understanding object references is essential for writing correct Python programs.
